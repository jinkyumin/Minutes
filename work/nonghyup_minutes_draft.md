# 회의록 - 농협 하나로마트 입점 관련 결제 시스템(VAN) 협의

- 원본 파일: 농협 260401_111101.m4a
- 전사 파일: nonghyup_app_transcript.txt
- 주제: 농협 하나로마트 입점 시 POS, VAN, 정산 구조 및 협상 방향 검토

## 1. 회의 요약

농협 하나로마트 입점 시 다이소 POS와 셀프계산대 운영 구조를 유지하면서 결제 VAN을 농협VAN으로 전환해야 하는지 기술, 정산, 운영 관점에서 검토함. 기존 롯데마트 사례는 다이소 장비와 NICE VAN을 기반으로 카드 매출 데이터를 대사 후 롯데 측에 일괄 전달하는 구조임. 농협도 유사하게 특정매입 계약 방식으로 운영될 가능성 있음.

다만 농협 측에서 농협VAN 사용을 요구하고 있어, 기존 NICE VAN 유지 가능성 또는 NICE 중계 서버를 통한 농협VAN 라우팅 가능성 우선 확인 필요. 농협VAN 직접 적용은 POS 통신 모듈, 단말기, 인증, 장애 대응 측면에서 리스크가 커 최후 대안으로 관리 필요.

## 2. 핵심 카테고리별 정리

### 2-1. 현재 롯데마트 운영 구조

| 항목 | 내용 |
|---|---|
| 장비 | 셀프계산대는 다이소 장비 사용 |
| 유인 POS | 2대 운영: 다이소 POS, 마트 POS |
| 마트 POS 용도 | 현금 결제 중심 |
| 다이소 유인 POS 용도 | 셀프계산대 반품 전용 |
| VAN | NICE VAN 사용 |
| 정산 흐름 | NICE가 카드 매출 자료 정리, POS 데이터와 대사 후 롯데에 전달 |
| 매출 인식 | 롯데는 다음 날 전달받은 데이터를 통합 매출로 처리 |
| 회계 처리 | 유통점 정산과 유사하게 월 1회 수수료 차감 후 매출 처리 |

### 2-2. 농협 하나로마트 적용 시 예상 구조

- 농협 하나로마트도 셀프계산대 중심 운영 예상.
- 장비는 다이소 장비 사용, 사업자와 결제 주체는 농협 측 구조 가능성 있음.
- 특정매입 계약 구조에서는 농협 측 매출 발생 필요.
- 단순 임대수입만 발생하는 구조는 감사 이슈 가능성 있음.
- 5월 전주점은 임대계약 형태로 자사 VAN 사용 가능 언급.
- 8월 오픈 예정 건부터 특정매입 계약 및 VAN 이슈 본격 적용 가능성 있음.

### 2-3. 농협VAN 사용 요구와 쟁점

- 농협 측은 농협VAN 사용 요구 중인 것으로 파악.
- 농협VAN은 외부 영업 사례가 거의 없어 안정성 및 장애 대응 경험 불명확.
- 농협VAN 사용 시 다이소 POS 프로그램의 결제 통신 모듈 변경 필요.
- 카드 리더기, 단말기, 인증, 하드웨어 제공 가능 여부 확인 필요.
- 농협VAN 강요는 특정 VAN 사용 강제라는 점에서 공정거래법 이슈 가능성 있음.

### 2-4. 기술 리스크

- POS 프로그램은 다이소 프로그램 유지 필요.
- VAN 변경 시 결제 통신 모듈 변경 필요.
- 기존 NICE 리더기 사용 불가 가능성 있음.
- 농협VAN용 리더기/단말기 교체 가능성 있음.
- 농협VAN이 다이소 POS 임베디드 형태에 맞는 하드웨어 제공 가능 여부 불명확.
- VAN 변경 시 인증 재취득 가능성 있음.
- 농협VAN 장애 시 외부 운영 사례 부족으로 장애 대응 안정성 우려.

### 2-5. 운영 및 정산 리스크

- NICE와 농협VAN 병행 시 매일 데이터 수신 및 대사 업무 증가 가능성 있음.
- POS 장애 또는 데이터 미전송 발생 시 다이소 책임 전가 가능성 있음.
- 특정매입 계약 구조에서는 농협 측 매출 발생 필요.
- 다이소는 유통점 정산처럼 매출 데이터를 받아 처리하는 방향이 바람직.
- 내부 별도 분개 처리와 복잡한 회계 처리는 최소화 필요.

## 3. 검토 대안

### A안: NICE VAN 유지

- 다이소는 기존 NICE VAN 구조 유지.
- 농협은 NICE와 계약 또는 정산 구조 협의.
- 다이소 시스템 변경이 가장 적고 운영 안정성 가장 높음.
- 농협이 농협VAN 사용을 강하게 요구할 경우 설득 논리 필요.

### B안: NICE 중계 서버를 통한 농협VAN 라우팅

- 결제는 기존 NICE 중계 서버를 통과하되, 농협 하나로마트 거래만 농협VAN으로 라우팅하는 구조 검토.
- 다이소 입장에서는 기존 구조를 최대한 유지하면서 농협VAN 명분 일부 충족 가능.
- NICE와 농협VAN 간 계약 관계, 비용, 기술 가능성 확인 필요.
- 현실적 1순위 검토안으로 관리 필요.

### C안: 농협VAN 직접 적용

- POS 결제 통신을 농협VAN으로 직접 전환.
- 단말기/리더기 교체, 인증, 개발, 테스트, 장애 대응 리스크 가장 큼.
- 일정과 비용 측면에서 최후 대안으로 관리 필요.

## 6. 결론 및 권고

우선 NICE와 협의하여 기존 NICE VAN 구조 유지 또는 NICE 중계 서버를 통한 농협VAN 라우팅 가능 여부 확인 필요. 농협VAN 직접 적용 방식은 POS 통신, 단말기, 인증, 장애 대응 리스크가 크므로 최후 대안으로 관리 필요.

농협 측 요구가 실제 필수 조건인지, 단순 요청 또는 내부 수익 확보 목적의 주장인지 별도 확인 필요. 협상 방향은 `NICE VAN 유지`, `NICE 중계 라우팅`, `농협VAN 직접 적용` 순서로 단계적 검토 권고.
